RUPAK LOBBY LEDGER — LIVE, MOBILE-FIRST MULTI-USER WEBSITE

What this build does:
- Anyone can create an account with username, email and password.
- Each account has its own ledger; users can only edit their own records.
- A public profile link is /?u=username. Anyone with that link can view that user's ledger rows, totals and QR. Public visitors cannot edit.
- Mobile-first responsive interface; can be added to the phone home screen from Chrome.
- Lobby records, payments, QR upload/remove and CSV export.
- Cloud database and QR storage use Supabase. Hosting can be Vercel.

IMPORTANT PRIVACY:
Public profile links show lobby history, earnings, payments and QR to anyone who knows the username link. Do not enter private/confidential information. To make ledgers private instead, change the public-view requirement and database policies before launch.

SETUP (PC needed for first publish; daily use is mobile):
1. Create a Supabase project at https://supabase.com/ and keep the project URL + anon/publishable key.
2. Supabase > SQL Editor > New query. Paste all of supabase-schema.sql and click Run.
3. Supabase > Authentication > Providers > Email. For easiest first test, turn email confirmation OFF; enable it later if desired.
4. Copy .env.example to a new file named .env. Fill in VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY.
5. Open terminal in this folder and run:
   npm install
   npm run build
6. Publish this folder to a GitHub repository (do not upload .env). Import that repo into https://vercel.com/ .
7. In Vercel project Settings > Environment Variables add:
   VITE_SUPABASE_URL = your Supabase project URL
   VITE_SUPABASE_ANON_KEY = your Supabase anon/publishable key
   Redeploy.
8. In Supabase Authentication > URL Configuration set Site URL to your Vercel website URL.
9. Open the Vercel URL on mobile Chrome, create an account, add records. Share profile link from the dashboard.

LOCAL PREVIEW:
npm install
npm run dev
Open the local URL shown by Vite.

SECURITY:
- Never put Supabase service_role/secret key in .env or frontend.
- Only the anon/publishable key belongs in VITE_SUPABASE_ANON_KEY.
- SQL policies restrict edits to the signed-in owner; anonymous users have read-only public profile/ledger access.
- Public ledger information is visible by username link. This is intentional in this build.
- This starter has not been deployed or tested against your Supabase project. Test with two accounts before sharing widely.
